# Contributing to VoiceCycle

Thanks for your interest. Bug reports from real phones are the most valuable contribution, because background reliability differs between brands and Android versions.

## Reporting a bug

Use the bug report template. Include your phone model, Android version, the battery setting for VoiceCycle, and the output of:

```
adb logcat -d -s VoiceCycle:I
```

## Development setup

See [docs/BUILDING.md](docs/BUILDING.md) for the toolchain, then:

```bash
npm install
npm run android        # builds and installs the development build on a connected phone
```

## Before you open a pull request

All four checks must pass:

```bash
npm run typecheck
npm run lint
npm test
npm run test:native    # or: cd android && ./gradlew :voicecycle-player:testDebugUnitTest
```

## Ground rules

- **Playback timing belongs in native code.** Never add JavaScript timers that drive playback. The UI only renders snapshots from the playback service. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- **Keep the state machine pure.** `CycleStateMachine` has no Android imports. Randomness and time are passed in with events. Add a JUnit test for every new transition.
- **Do not edit `android/`.** It is generated by `expo prebuild`. Change `app.json`, a config plugin, or the local module instead.
- **Add dependencies with `npx expo install`** so versions match the Expo SDK.
- **No network, analytics or accounts.** VoiceCycle is offline by design.
- Use [Conventional Commits](https://www.conventionalcommits.org/) such as `feat:`, `fix:` or `docs:`.
- If behaviour changes, update the README, the docs and `CHANGELOG.md` in the same pull request.
